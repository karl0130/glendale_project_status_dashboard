# Glendale Korea Project Dashboard

부티크 컨설팅 팀(10명 미만)을 위한 프로젝트 일정 · 인력 리소스 · 주간 업무 보고 통합 대시보드.
빌드 도구 없이 동작하는 정적 사이트라서 **GitHub Pages에 그대로 올라간다.**

## 화면

| 경로 | 화면 | 내용 |
|---|---|---|
| `#/overview` | Overview | 핵심 지표 2종 + 금주 휴가 · 2주 단위 프로젝트 간트 · 2주 단위 리소스 간트 |
| `#/projects` | Project Status | 프로젝트 등록/수정 + 4주 간트 + 전체 목록 |
| `#/resources` | Resource Planning | 인원별 월간 투입 간트 (입력 없이 자동 산출) |
| `#/weekly` | Weekly Work Updates | 주간 업무 기입 + 작성자·프로젝트별 주간 간트 + 상세 보고 |
| `#/vacations` | 휴가 관리 | 팀 전체 휴가 일정 **조회 전용** |
| `#/mypage` | My Page | 내 연차 현황 · 휴가 신청/수정/취소 · (승인권자) 승인 대기 처리 |
| `#/data` | 설정 | 시트 연결 · 백업 |

### 화면 사이의 연결

```
Project Status (프로젝트 · PM · 팀원 · 기간)  ─┐
                                              ├─→ Resource Planning (자동 산출, 입력 없음)
휴가 관리 (휴가 일정) ────────────────────────┘   └─→ Overview 금주 휴가 · 리소스 간트
                                                  └─→ Weekly Work Updates 간트
```

리소스 간트와 주간 업무 간트에서 휴가는 **별도 행으로 빠지지 않는다.** 프로젝트 바가 휴가
기간에 끊기고 같은 줄 그 자리에 휴가 블록이 들어간다. 두 프로젝트를 동시에 하면 줄이 둘로
나뉘고 휴가는 양쪽 모두에 표시된다.

## 데이터가 저장되는 방식

출처가 두 가지이고, 구글 로그인 여부로 갈린다.

```
[로그인 전]  local 모드
  data/*.json  →  화면
                    ↓ 입력
                 localStorage   ← 이 브라우저에만. 공유 안 됨

[로그인 후]  sheets 모드
  Google Sheets  ⇄  화면        ← 저장 즉시 팀 전체에 반영
       (localStorage 는 다음 진입 때 즉시 렌더용 캐시로만 쓴다)
```

우측 상단 **구글 로그인** 버튼으로 연결한다. 한 번 연결하면 이후 방문에서는 팝업 없이
자동으로 붙는다 (세션이 살아 있는 동안).

### 서버가 왜 필요 없나

Google Identity Services 의 토큰 클라이언트는 **클라이언트 시크릿을 쓰지 않는 흐름**이라
브라우저에서 직접 액세스 토큰을 받는다. 이후 `sheets.googleapis.com` 을 그냥 `fetch` 한다.
중간에 서버가 낄 자리가 없다.

### 접근 통제

페이지 자체는 공개지만 **데이터는 공개가 아니다.**

1. OAuth 앱이 **Internal** 이라 회사 Workspace 계정만 로그인된다
2. 스프레드시트의 **Drive 공유 권한**이 있는 사람만 읽고 쓴다

권한 없는 사람이 URL 로 들어오면 로그인은 되지만 시트를 못 읽어 빈 화면을 본다.
사람이 나가면 Drive 에서 공유만 해제하면 된다 — 코드는 건드릴 필요 없다.

`config.js` 의 `clientId` 와 `spreadsheetId` 는 **비밀값이 아니다.** 브라우저에 그대로
노출되는 것이 정상이고, 공개 레포에 있어도 위 두 겹이 막아준다.

### 동시 저장 충돌

시트에는 트랜잭션이 없다. `_meta` 탭의 `revision` 으로 낙관적 락을 건다 — 읽을 때 받은
번호와 저장 직전에 다시 읽은 번호가 다르면 저장을 거부하고 "다른 사람이 먼저 저장했습니다"
를 띄운다. 덮어쓰기가 조용히 일어나지 않는다.

### 로그인 없이 쓰기 (오프라인 · 초기 세팅용)

로그인하지 않아도 `data/*.json` 으로 화면은 다 돈다. 이때 입력한 내용은 그 브라우저에만
남고, `설정` 화면에서 JSON 을 내려받아 `data/` 에 커밋하는 옛 방식으로
반영할 수 있다.

### 아카이빙

**구글 시트의 버전 기록이 아카이브다.** 시트에서 `파일 → 버전 기록 → 버전 기록 보기` 로
언제든 과거 시점을 보고 되돌릴 수 있다. 별도 아카이브 테이블도, 커밋도 필요 없다.

누가 언제 저장했는지는 `_meta` 탭의 `savedBy` / `savedAt` 에 남는다.

월말 보고용 단일 파일이나 구글 밖 백업이 필요하면 `설정` 화면에서 전체
스냅샷을 내려받는다.

### ⚠️ `data/*.json` 에 실제 데이터를 커밋하지 말 것

시트에 연결한 뒤로 `data/*.json` 은 **저장 경로가 아니다.** 로그인하지 않은 사람에게
보이는 화면을 채우는 표본 데이터일 뿐이다.

`data/` 는 GitHub Pages 로 그대로 공개된다. 시트의 실제 데이터를 여기에 커밋하면
고객사명과 인력 배치가 URL 아는 사람 누구에게나 보인다 — 시트로 옮긴 이유가 사라진다.
그래서 내보내기-커밋 UI 는 아예 없앴다. `설정` 화면에 남은 것은 연결 상태, 최신 내용
다시 받기, 백업 파일 내려받기 셋뿐이다.

### 데이터 파일

시트 탭 4개와 `data/*.json` 4개는 1:1 로 대응한다. 시트에서는 **1행이 헤더**이고,
읽을 때 열을 **헤더 이름으로** 찾으므로 시트에서 열 순서를 바꿔도 깨지지 않는다.
`memberIds` 처럼 배열인 값은 `emp-03,emp-05` 형태로 한 셀에 넣는다.

| 시트 탭 | 파일 | 입력 위치 |
|---|---|---|
| `employees` | `data/employees.json` | 직접 편집 |
| `projects` | `data/projects.json` | Project Status |
| `weekly_updates` | `data/weekly-updates.json` | Weekly Work Updates |
| `vacations` | `data/vacations.json` | 휴가 관리 |
| `_meta` | — | 자동 (리비전) |

| 파일 | 내용 | 입력 위치 |
|---|---|---|
| `data/employees.json` | 구성원 명단 | 직접 편집 |
| `data/projects.json` | 프로젝트 (고객사, End client, 상태, PM, 팀원, 기간) | Project Status |
| `data/weekly-updates.json` | 주간 수행 업무 | Weekly Work Updates |
| `data/vacations.json` | 휴가 일정 | 휴가 관리 |

Resource Planning은 **입력이 없다.** `projects.json`의 PM·팀원·기간에서 자동으로 산출된다.

## 로컬 실행

`fetch()`와 ES 모듈을 쓰므로 `index.html`을 파일로 직접 열면 동작하지 않는다. 로컬 서버가 필요하다.

```bash
python -m http.server 8000
# 또는
npx serve .
```

→ http://localhost:8000

## GitHub Pages 배포

1. 이 레포를 GitHub에 푸시
2. Settings → Pages → Source: **GitHub Actions** 선택
   (`.github/workflows/pages.yml` 이 포함되어 있어 푸시할 때마다 자동 배포된다)
3. `https://<계정>.github.io/<레포명>/` 로 접속

`Deploy from a branch` 방식을 쓴다면 워크플로 없이 브랜치 루트를 그대로 지정해도 된다. `.nojekyll` 이 있어 Jekyll 처리는 건너뛴다.

> **주의 — 공개 범위.** GitHub Pages로 배포한 사이트는 레포가 private이어도 **URL을 아는 사람은 누구나 볼 수 있다.** 고객사명·인력 배치가 외부에 노출돼도 무방한 수준인지 먼저 판단하고, 접근 제어가 필요하면 Cloudflare Pages + Access 등으로 옮기는 것을 권한다.

## 휴가 승인

```
팀원이 My Page 에서 신청  →  상태 '신청'  →  승인권자 My Page 에 대기 목록
                                              ├ 승인 → 연차에서 차감, 일정 확정
                                              └ 반려 → 일정에서 제외, 연차 복구
```

- **승인권자**는 `employees` 탭의 `canApprove` 가 `TRUE` 인 사람. 상단 계정 아이콘에
  대기 건수가 배지로 뜬다.
- **메일 알림**이 자동으로 나간다. 신청하면 승인권자에게, 승인·반려하면 신청자에게.
  Gmail API 를 브라우저에서 직접 호출하므로 서버도 외부 메일 서비스도 필요 없다.
  발신자는 **그 동작을 한 사람의 계정**이다 (신청 알림은 신청자, 결재 알림은 승인권자).
  메일 실패가 신청·결재를 막지 않는다 — 저장은 이미 끝났고, 화면이 "저장은 됐고 메일만
  안 갔다" 를 구분해 알린다. 받는 사람의 `email` 이 비어 있으면 발송을 시도하지 않는다.
- **승인권자 본인의 휴가는 신청 단계 없이 바로 승인**된다. 자기가 자기를 승인하는
  화면은 의미가 없다.
- 신청 · 수정 · 취소는 **My Page 에서만** 한다. `휴가 관리` 탭은 팀 전체가 보는
  조회 화면이라 남의 일정을 건드릴 수 있으면 안 된다.
- **사유(비고)는 공유 화면에 싣지 않는다.** 본인의 My Page 와 승인권자의 대기 목록에만
  보인다. 간트 툴팁에도 넣지 않는다.
- 미승인 휴가도 간트에 **점선 + `(대기)` 라벨**로 표시한다. 안 보이면 그 기간에 일을
  배정했다가 나중에 꼬인다.

### 공휴일

`data/holidays.json` 이 대한민국 공휴일 목록이다. 설날 · 추석 · 부처님오신날은 음력이라
매년 날짜가 바뀌고 대체공휴일 규칙까지 붙어서 계산으로는 구할 수 없다.

**GitHub Actions 가 매년 12월 1일에 자동 갱신하고 커밋한다**
(`.github/workflows/holidays.yml`). 3년치를 굴리므로 항상 다음 해 달력이 미리 들어 있다.
공휴일이 그대로면 커밋하지 않는다 — 그래서 생성 시각을 파일에 넣지 않았다.

임시공휴일처럼 갑자기 지정되는 날은 Actions 탭에서 `Run workflow` 를 눌러 다시 받거나,
`data/holidays.json` 의 `days` 에 직접 한 줄 추가하면 된다.

공휴일은 **영업일 계산 전부**에 반영된다 — 연차 차감, 프로젝트 잔여 영업일, 휴가 표의
영업일, 간트의 음영과 날짜 색까지. 판정은 `assets/js/holidays.js` 한 곳을 거친다.
주말만 빼는 계산이 흩어져 있으면 어디는 반영하고 어디는 안 하는 상태가 되기 때문이다.

```bash
# 손으로 갱신하려면
pip install holidays && python scripts/gen_holidays.py
```

### 연차 계산

| 항목 | 규칙 |
|---|---|
| 부여 일수 | `employees.annualLeave` (개인별). 비어 있으면 15일 |
| 산정 기간 | **입사일 기준** 1년. `employees.joinDate` 가 비어 있으면 회계연도(1/1–12/31) |
| 반차 | 기간과 무관하게 **0.5일** |
| 연차 · 기타 | **주말과 공휴일을 뺀** 영업일 수만큼 차감 |
| 공가 · 경조휴가 | **차감하지 않음** (`config.js` 의 `LEAVE_POLICY.exempt`) |

`잔여 = 부여 − 승인분 − 대기분`. 대기분을 미리 빼두지 않으면 신청해둔 것을 잊고
초과 신청하게 되고, 대기분만 빼면 반려됐을 때 되돌려야 한다. 그래서 둘 다 표시한다.

### 권한의 한계 — 알고 쓸 것

이 앱은 **브라우저에서만 동작**하고, 팀원은 시트에 편집 권한이 있어야 저장이 된다.
즉 마음먹으면 **시트를 직접 열어 자기 휴가를 `승인` 으로 바꿀 수 있다.** 대시보드 UI 는
그것을 막지 못한다.

지금 규모(8명)에서는 신뢰 기반으로 충분하다고 보고 이 구조를 택했다. 실제로 강제하려면
Apps Script 웹앱을 중계로 두고 팀원에게서 시트 권한 자체를 빼야 한다.

## 타이포그래피

본문은 **나눔스퀘어**, jsDelivr CDN에서 불러온다 (`index.html` 상단).

나눔스퀘어는 **300 / 400 / 700 / 800** 네 단계만 있다. 그래서 `style.css` 의 `font-weight` 는
`400` · `700` · `800` 만 쓴다 — 500이나 600 같은 중간값을 쓰면 브라우저가 임의로 반올림해
의도와 다른 굵기가 나온다.

폐쇄망이라 CDN을 못 쓴다면 woff2 를 `assets/font/` 에 내려받고 `index.html` 의 `<link>` 를
로컬 `@font-face` 로 바꾸면 된다. 나머지는 그대로 동작한다.

## 시각화 규칙

일관되게 지킨 규칙들 (수정할 때 함께 유지할 것):

- **색은 프로젝트를 따라간다.** 필터나 화면이 바뀌어도 같은 프로젝트는 같은 색이다. 색을 순위/행 번호에 배정하지 않는다.
- **카테고리 색은 8슬롯이 상한.** 9번째 프로젝트부터는 새 색을 만들지 않고 중립 회색으로 접는다. 슬롯 순서 자체가 색각이상 대비 안전장치이므로 재배열하지 않는다.
- **상태색(good/warning/critical)은 예약어.** 프로젝트 식별에 전용하지 않고, 항상 아이콘 + 글자와 함께 쓴다.
- **모든 차트에 표 보기 쌍이 있다.** 색만으로 갇히는 정보가 없다.
- **바 라벨은 잘리지 않는다.** 바 안에 안 들어가면 바깥으로 내보내고, 바깥에도 자리가 없으면 감춘다 (옆 바 위에 글자가 겹치는 것이 라벨 없는 것보다 나쁘다). 감춘 값은 툴팁과 표 보기에 그대로 남는다.
- **휴가로 쪼개진 바는 조각마다 이름을 달지 않는다.** 화면에 보이는 구간 기준으로 가장 넓은 조각 하나만 라벨을 갖는다.
- 격자/축은 1px 실선 헤어라인. 점선은 임계선으로 오독되므로 쓰지 않는다.
- **안내 문구는 마침표 없는 명사형**으로 통일한다 ("~합니다." ✗ / "~자동 반영" ○). 설명이 여러 갈래면 배열로 넘겨 한 갈래가 한 줄을 차지하게 한다 — 한글이 문장 도중에 접히는 것을 막기 위함.

## 최초 세팅 (한 번만)

1. **Google Cloud Console** — 프로젝트 생성 → **`Google Sheets API` 와 `Gmail API` 사용 설정** →
   OAuth 동의 화면 **Internal** → 사용자 인증 정보에서 **웹 애플리케이션** 클라이언트 생성.
   승인된 JavaScript 원본에 `https://<계정>.github.io` 와 `http://localhost:8000` 등록.
   리디렉션 URI 는 비워둔다.
   요청 범위는 `spreadsheets` · `userinfo.email` · `gmail.send` 세 개다. `gmail.send` 는
   민감 스코프지만 Internal 앱이라 구글 검토가 필요 없다.
2. 발급된 **클라이언트 ID** 와 스프레드시트 ID 를 `assets/js/config.js` 에 넣는다.
3. 스프레드시트를 팀원에게 **편집 권한**으로 공유한다.
4. 대시보드에서 구글 로그인 → `설정` → **시트 초기화** 를 한 번 누른다.
   탭 5개와 헤더가 만들어지고 현재 데이터가 들어간다.
5. `employees` 탭의 **`email` 열을 채운다.** 로그인한 구글 계정과 직원 레코드를 잇는
   유일한 연결고리다. 비어 있으면 "지금 로그인한 사람이 누구인지"를 알 수 없다.

## 구조를 바꾸고 싶다면

데이터 계층은 `store.js` 뒤에 숨어 있다. 화면 코드 6개는 `all` / `byId` / `upsert` /
`remove` 만 쓰므로, 백엔드를 갈아끼워도 손댈 필요가 없다.

- `assets/js/config.js` — 클라이언트 ID · 시트 ID · 탭과 열 정의
- `assets/js/google/auth.js` — 토큰 발급 · 갱신 · 로그인 상태
- `assets/js/google/sheets.js` — 시트 행 ↔ 객체 변환, 읽기/쓰기/초기화
- `assets/js/google/mail.js` — Gmail API 발송 (MIME 조립 · 한글 헤더 인코딩)
- `assets/js/notify.js` — 휴가 알림 메일 문안

다른 백엔드(Supabase, Cloudflare D1 등)로 옮길 때도 `store.js` 의 `pull` / `pushCollection`
두 곳만 바꾸면 된다.
